**커밋된** 스윙 전략을 깨끗한 환경에서 비용·갭 체결 스트레스 백테스트하고, 결과를 기준선(2026-10-02)과 비교한다.
배경: 백테스트는 항상 트리거·손절가에 체결된다고 가정해 거래당 약 0.06R 낙관적이었다(PROJECT_CHARTER 2026-10-02).
인자 `$ARGUMENTS`가 있으면 보유기간 목록으로 쓴다(기본 `10 15 20`).

## 1. 깨끗한 환경 (작업트리에서 돌리지 않는다)
작업트리에는 다른 세션의 미커밋 백테스트 수정이 있을 수 있어, 거기서 돌리면 **배포된 전략이 아니라 미완성 코드**를 잰다.
```bash
WT=<스크래치패드>/bt
git worktree add --detach "$WT" HEAD -q
cp data/evolution/champion.json "$WT/data/evolution/champion.json"
cd "$WT" && corepack pnpm install --frozen-lockfile >/dev/null 2>&1
```

## 2. 추출기 (`$WT/extract.mts`)
프로젝트 자신의 `computeExpectancy`/`toRMultiple`을 쓴다 — 기대값을 따로 계산하면 채점 불일치가 생긴다.
체결된 거래를 청산일 순으로 정렬해 기대값·누적R·최대낙폭(R)·PF·OOS 승률을 한 줄로 출력한다.
주의: 리포트는 최근 200건만 담으므로 누적R은 상대 비교용이다.

## 3. 비용 스트레스
```bash
for c in 0.35 0.70 1.75; do for d in 10 15 20; do
  ROUND_TRIP_COST_PCT=$c SWING_BACKTEST_HOLDING_DAYS=$d SWING_BACKTEST_LOOKBACK_DAYS=1000 SWING_BACKTEST_FORCE=true \
    corepack pnpm start:swing:backtest >/dev/null 2>&1
  TAG="비용 ${c}% 보유 ${d}일" npx tsx extract.mts
done; done
```
9회 약 10분 — `run_in_background`로 돌린다.

## 4. 갭 체결 (측정용 패치 — 커밋하지 않는다)
워크트리의 `server/swingBacktestAgent.ts`에만, `GAP_FILLS=1`일 때:
- 매수: `max(진입일 시가, 트리거)` 기준으로 수익률 계산
- 손절: 진입 **다음 봉부터** `min(그날 시가, 손절선)` (진입 봉은 시가가 체결 전이라 제외)
- 목표가는 그대로(유리한 방향 가정 금지)
다른 세션의 `server/dailyBarExecution.ts`가 같은 가정이다 — 이미 백테스트에 들어가 있으면 패치 대신 그걸로 잰다.

## 6. 판단과 정리
- 비용 5배에서 기대값이 0 이하가 되거나 **순위가 뒤바뀌면** 보고한다(회전율 높은 설정이 먼저 무너진다)
