다른 세션의 미커밋 작업을 보존한 채 로컬 커밋을 푸시하고, **실제로 도착했는지(CI)**까지 확인한다. 순서대로, 생략 없이:

## 1. 상태 파악
- `git fetch origin -q` 후 `git status -sb | head -1` — ahead/behind 확인
- `git log HEAD..origin/main --oneline | grep -v "chore(data)"` — 원격에 **데이터 커밋이 아닌 것**이 있으면 멈추고 무엇인지 보고한다
  (다른 세션이 코드를 푸시했을 수 있다 — 리베이스 충돌 가능)
- `git status --short | wc -l` — 보존할 미커밋 파일 수를 기록해 둔다(복원 후 같아야 함)
- `git diff --cached --name-only` — 스테이지에 남은 것이 있으면 멈춘다

## 2. 보존 → 리베이스 → 푸시 → 복원
```bash
git stash push -u -q -m "other-session-wip-$(date +%s)" 2>&1 | grep -v "LF will"
git rebase origin/main -q
git push origin main 2>&1 | tail -1
git stash pop -q 2>&1 | grep -v "LF will"
```
- `stash push`는 CRLF 경고를 수백 줄 낼 수 있다(증거 파일 등) — 걸러서 본다
- 리베이스 충돌이 나면 **절대 `--force`나 `checkout --`로 정리하지 않는다.** `git rebase --abort` 후 `git stash pop`으로 원상복구하고 보고한다

## 3. 복원 검증
- `git status -sb | head -1` → `## main...origin/main`(차이 없음)이어야 함
- `git status --short | wc -l` → 1단계에서 센 수와 같아야 함
- `git stash list | wc -l` → 0이어야 함(남아 있으면 복원 실패 — 보고)
- `git worktree list | wc -l` → 1이어야 함(임시 워크트리 잔여물)

## 4. 도착 확인 (생략 금지 — "푸시했다"는 완료가 아니다)
- 1~2분 뒤 `gh run list --workflow=ci-tests.yml --repo qkrehgk1-wq/korea-swing-agent --limit 1`
- 실패면 `gh run view <id> --log-failed`로 원인을 보고 고친다. 실패 상태로 두고 끝내지 않는다
- 데이터 커밋(`[skip ci]`)만 쌓인 동안은 CI 테스트가 돌지 않는다 — 정상
