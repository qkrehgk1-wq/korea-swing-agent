다른 세션의 미커밋 작업을 보존한 채 로컬 커밋을 푸시하고, **실제로 도착했는지(CI)**까지 확인한다. 순서대로, 생략 없이:

## 1. 상태 파악
- `git fetch origin -q` 후 `git status -sb | head -1` — ahead/behind 확인
- `git log HEAD..origin/main --oneline | grep -v "chore(data)"` — 원격에 **데이터 커밋이 아닌 것**이 있으면 멈추고 무엇인지 보고한다
  (다른 세션이 코드를 푸시했을 수 있다 — 리베이스 충돌 가능)
- `git status --short | wc -l` — 보존할 미커밋 파일 수를 기록해 둔다(복원 후 같아야 함)
- `git diff --cached --name-only` — 스테이지에 남은 것이 있으면 멈춘다

## 2. 보존 → 리베이스 → 푸시 → 복원
```bash
git stash push -u -q -m "other-session-wip-$(date +%s)" 2>&1 | grep -v "LF will"
git rebase origin/main -q
git push origin main 2>&1 | tail -1
git stash pop -q 2>&1 | grep -v "LF will"
```
- `stash push`는 CRLF 경고를 수백 줄 낼 수 있다(증거 파일 등) — 걸러서 본다
- 리베이스 충돌이 나면 **절대 `--force`나 `checkout --`로 정리하지 않는다.** `git rebase --abort` 후 `git stash pop`으로 원상복구하고 보고한다

## 3. 복원 검증
- `git status -sb | head -1` → `## main...origin/main`(차이 없음)이어야 함
- `git status --short | wc -l` → 1단계에서 센 수와 같아야 함
- `git stash list | wc -l` → 0이어야 함(남아 있으면 복원 실패 — 보고)
- `git worktree list | wc -l` → 1이어야 함(임시 워크트리 잔여물)

## 4. 도착 확인 (생략 금지 — "푸시했다"는 완료가 아니다)
- 1~2분 뒤 `gh run list --workflow=ci-tests.yml --repo qkrehgk1-wq/korea-swing-agent --limit 1`
- 실패면 `gh run view <id> --log-failed`로 원인을 보고 고친다. 실패 상태로 두고 끝내지 않는다
- 데이터 커밋(`[skip ci]`)만 쌓인 동안은 CI 테스트가 돌지 않는다 — 정상

## 5. 보고
- 푸시한 커밋 목록(해시·제목), CI 결과, 보존한 파일 수
- 그 변경이 **실제로 효과를 내는 시점**(다음 데일리 실행 KST 06시경, 일요일 알파 리서치 등)

## 6. 2026-10 추가 함정 (실제로 푸시가 막히거나 작업이 꼬였던 경우)
- **이메일 비공개 거부(`GH007 ... private email address`):** GitHub 계정에 "이메일 노출 차단"이 켜져 있으면 작성자·**커미터** 이메일이 실제 주소인 커밋은 푸시가 거부된다.
  `git rebase`는 **커미터를 현재 설정 이메일로 덮어쓴다** — 작성자를 noreply로 맞춰도 리베이스 후 다시 걸린다.
  리베이스·커밋 때 `GIT_COMMITTER_NAME=qkrehgk1-wq GIT_COMMITTER_EMAIL="$(gh api user -q .id)+qkrehgk1-wq@users.noreply.github.com"`를 같이 주고,
  이미 만든 커밋은 `--author`와 같은 값으로 `git commit --amend --no-edit`(`--reset-author`와 `--author`는 함께 못 쓴다). 푸시 전 `git log -1 --format='%ae %ce'`로 둘 다 확인한다.
- **stash pop 충돌(`data/journal/recommendations.json`):** 다른 세션이 로컬에서 저널을 고쳤고 그 사이 CI 데이터 커밋이 같은 파일을 바꾸면 pop이 충돌로 멈추고 스태시가 남는다(나머지 파일은 스테이징된 채 복원됨).
  스태시를 버리지 말 것 — 항목(날짜|티커|관찰여부) 단위로 병합한다: 원격을 기준으로, 그쪽 신규·수정 항목을 얹는다(같은 항목을 양쪽이 고쳤으면 원격 우선). 쓴 뒤 `git reset -q`로 스테이징만 풀고,
  스태시의 추적 파일이 작업트리와 같은지(`git diff --quiet stash@{0} -- <파일>`)와 미추적 파일이 모두 있는지 확인한 다음 `git update-ref refs/backup/...`로 백업 후 drop.
- 1단계의 `git stash push -u`가 138개·수천 개 미추적 파일 때문에 몇 분 걸릴 수 있다 — 도구 타임아웃을 넉넉히(600초) 주고, 타임아웃으로 백그라운드로 넘어가면 끝난 뒤 `git stash list`/`git status`부터 확인한다.
