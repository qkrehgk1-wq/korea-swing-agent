### 운영 안전 관행 (일반론 — 출처: 업계 블로그·규제 사례, 한국 특화 아님)
- 단계적 배포: 백테스트 → 워크포워드 → 몬테카를로 → 페이퍼 → 섀도 → 소액 실거래 → 확대. 각 단계는 통과 기준이 있어야 다음으로.
- 킬스위치: 미체결 주문 취소 + 신규 신호 차단 + 기록. 트리거 후보: 데이터 지연, 위험 한도 초과, 주문 거부 반복, 비정상 체결률, 브로커 연결 끊김. **실제 조건에서 테스트하지 않은 킬스위치는 흔한 실패 원인.**
- 한도: 종목별·전체 노출 한도(**미체결 주문도 노출에 포함**), 일 손실 한도 도달 시 당일 중단, 브로커 쪽 독립 제한을 2중으로.
- 페이퍼 졸업 기준(최소 기간·건수·백테스트 괴리 허용치)에 대한 **권위 있는 출처는 못 찾았다 [모름]** — 이 저장소의 자체 기준을 쓴다.

## 3. 시사점·권고 순서

1. **실거래 연결은 지금 하지 않는다.** 기준(라이브 30건 이상·R>0.1·PF≥1.2, V3 전진 45일·30건 이상)을 충족하기 전에는 증권사 키를 만들 이유가 없다.
2. **먼저 확인할 것(지휘관 몫, 코드 아님):** ① 소속 기관 윤리 담당에 주식 거래 관련 제한 문의 ② 키움 REST 공식 약관·호출 한도·모의투자 지원 TR 목록 확인 ③ api-id 등 블로그 상충 수치는 공식 명세로 확정.
3. **붙인다면 이 순서:** (a) 조회 전용 키로 잔고·체결 내역 읽기 → 저널과 대조(백테스트 대비 체결 괴리 실측에 쓸 수 있어 가치 큼) (b) 모의투자 계좌로 사람이 낸 주문의 기록만 비교 (c) 소액 수동 주문. 에이전트의 자동 주문은 범위 밖.
4. **실행 인프라:** 실거래 보조를 하게 되면 시각 정밀도가 필요한 부분은 Actions 크론이 아니라 별도 상시 환경이 필요하다. 지금 알림은 장 시작 전 정보 제공이라 지터가 문제 없다.
5. **계속 쌓는 것:** 라이브 표본, Jev 섀도(5/120), 섹터 상태 기록. 라이브 60건 무렵(약 한 달)에 전략 재설계 여부를 판단한다.
